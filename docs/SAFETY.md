# Safety, privacy and limitations — Pulse

> Pulse is a research prototype built during a 48-hour hackathon. It is **not a medical device**,
> has **not** been clinically validated, and must not be used for real health decisions.

## What the system is
A decision-support prototype for astronaut health monitoring during communication delays.
It combines deterministic alert rules, transparent trend analysis, a local retrieval corpus and a
constrained assistant. Every screening output is a **suggestion**, never a diagnosis.

## Non-negotiable safety properties implemented here
1. Clinical alarms are produced by the deterministic rules engine, not the LLM. All alarms and
   status levels still work with the model disabled (`LLM enabled: no` is visible in the UI).
2. The assistant can only raise the triage level above the rule level; guardrails enforce this in
   code (`app/llm/guardrails.py`), not only in the prompt.
3. Step-by-step clinical actions are checked against protocol text. Anything outside a protocol is
   flagged `outside_protocol` and generates a question for the ground team.
4. Dose numbers are rejected in free-text output; only `run_calculator` may provide numbers.
5. Notes, ground messages, booklet content and transcripts are delimited and treated as data in
   prompts. They can never issue instructions to the system.
6. All clinical content is synthetic and marked `NEEDS_CLINICAL_REVIEW` until a team physician
   validates it. The UI displays a "Draft — needs clinical review" badge.
7. Events are append-only. Corrections use `supersedes_id`; nothing is deleted.
8. Every alert, assessment, emergency access, ground message and sync action is written to an
   append-only audit trail.

## Known limitations
- All physiological data are synthetic; no real astronaut data are used.
- Thresholds and protocol content are starting points from public literature, not medically
  validated. They must be reviewed by a flight-medicine physician.
- Population reference ranges do not yet model sex, age, medication or individual baseline fully.
- Pulse-oximetry readings can be affected by skin pigmentation and motion. When SpO₂ conflicts
  with other signals, the system lowers confidence and asks for a re-measurement; it does not
  accuse the crew member.
- Correlation between crew symptoms and cabin environment is not causation. Small samples produce
  unstable estimates; we report confidence, not causal claims.
- The fallback assistant is template-based. It is deterministic and grounded in the same rules,
  but it is less flexible than a language model.
- Voice, image analysis, PDF export and remote model updates are roadmap items.
- The system cannot guarantee confidentiality: emergency access is logged and disclosed.

## Privacy model
- One local account per crew member, CMO, ground user and admin.
- Astronauts see their own detailed data and only crew aggregates.
- CMO sees the data a crew member shares, plus emergency-access data when a red case is open.
- Ground sees consultation packets and messages tied to cases, never routine raw telemetry.
- Emergency override is shown in plain language in the patient's UI and written to `audit_log`.

## Mental health
Phrases indicating self-harm or acute psychological crisis route to a dedicated support protocol,
inform the CMO and open a priority channel to ground. The content of that protocol must be reviewed
by a clinician; it is not a substitute for crisis care.

## Data and licences
All data are generated by `app/sim`. Clinical cards summarise public NASA Human Research Program
material and are original summaries, not copied text. Model usage terms (MedGemma / Health AI
Developer Foundations) must be verified before any public deployment. Code: MIT.
